Project proposal and rationale

Early Sepsis Prediction from the First Six ICU Hours: Supervised and Unsupervised Exploration

Scott Pryde · project_sepsis · 10 October 2026 · Redevelopment period: five weeks

1Proposal

The feasibility test confirmed that the PhysioNet/CinC Challenge 2019 dataset can support a leakage-safe pipeline that compares supervised and unsupervised AI methods on the same patients. This proposal redevelops that prototype over five weeks into a reproducible study and a basic application. The study predicts, from hours 0–5 of an ICU stay, whether a patient meets Sepsis-3 criteria within a fixed horizon, and explores label-free structure in the same data.

2Rationale

Why this dataset. It is open access, large (40,336 ICU patients), labelled hourly against Sepsis-3, and drawn from two hospital systems, allowing external validation without new data agreements. Its informative missingness is realistic, and published Challenge results give a benchmark.

Why both method families. Supervised models answer “who will develop sepsis?”. Unsupervised methods ask whether that risk is already visible as structure, such as subgroups or unusual physiology, before any label is used.

What the feasibility test established.

  • Data loads, validates and converts to one row per patient, with train-only preprocessing and patient-level splits.
  • Four supervised models and a self-contained HTML report already run end to end.
  • Issues to fix in redevelopment: an open-ended outcome window, inconsistent class weighting, no validation split, no cross-site test, and no unsupervised methods (tracked in IMPROVEMENTS.md).

3Data source and sampling

ElementDefinition
SourcePhysioNet/CinC Challenge 2019, version 1.0.0, training sets A and B: 40,336 patients, 2,932 septic (7.3%), 40 hourly variables plus SepsisLabel. Records have at least 8 hours and are capped at two weeks.
Unit and timingOne prediction per patient at the end of hour 5. Inputs are hours 0–5 only.
OutcomeSepsisLabel = 1 within a fixed horizon after hour 5 (primary 24 h; sensitivity analyses at 12 h and 48 h). The label already switches on 6 h before onset. Negatives need complete follow-up for the horizon.
SplitsStratified, patient-level, seeded 60 / 20 / 20 train / validation / test. External checks: train on A and test on B, then the reverse. Five repeated seeds for rank stability.
Uncertainty1,000 paired bootstrap resamples of the test patients for every reported metric.
Development sampleA stratified 10% subsample (about 4,000 patients) for fast iteration. All reported results use the full data.

4Synthetic data definition

A seeded generator (synthetic.py) produces files with the real schema, so tests, CI and the application can run without the real data. Synthetic results are never reported as findings.

PropertySpecification
SchemaIdentical PSV columns and order (40 variables + SepsisLabel). Files are prefixed s so they cannot be mixed with real p files.
PopulationConfigurable size (default 2,000; 40,000 for scale tests), split 50/50 between two simulated sites with different baseline means and lab-ordering rates.
Stay lengthLog-normal, bounded to 8–336 hours to match the real data's limits.
Risk and onsetLatent risk per patient sets the outcome via a logistic link, targeting 7% prevalence. Onset is at hour 4 or later; labels switch on 6 h before onset, as in PhysioNet.
SignalsVitals drift with latent risk towards onset, plus autocorrelated noise. Three planted subgroups (hypotensive, febrile, respiratory) test whether clustering recovers known structure.
MissingnessVitals 10–30% missing per hour; labs 80–98%, with ordering more frequent at higher risk (informative missingness).

6Environment and folder structure

A single Python 3.11 virtual environment holds both the ML pipeline and the application. Dependencies are split into optional extras so each part installs only what it needs.

py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1          # Windows
python -m pip install -U pip
pip install -e ".[ml,explore,app,dev]"
pip install -e ".[cnn]"               # PyTorch, optional
python scripts\download_data.py --flat
python scripts\make_synthetic.py --n 2000
pytest
sepsis-pipeline run --config configs\default.yaml
streamlit run app\Home.py

Extras: ml core pipeline; cnn PyTorch; explore UMAP; app Streamlit; dev tests and linting. .venv/, data/ and outputs/ stay out of Git.

Basic application. A read-only Streamlit app over saved run artifacts: cohort overview, model comparison, cluster explorer, and a patient viewer for synthetic patients. It never trains models.

FamilyModelsPurposeLibraries
Supervised, tabularLogistic Regression, Random Forest, XGBoostInterpretable baseline, non-linear ensemble, gradient boostingscikit-learn, xgboost
Supervised, sequence1D CNN with missingness masksTests whether hour-by-hour order adds signalPyTorch
Unsupervised, structurePCA, UMAP, k-means, Gaussian mixtureLabel-free views and patient subgroupsscikit-learn, umap-learn
Unsupervised, anomalyIsolation Forest, sequence autoencoderDoes “unusual” predict sepsis without labels?scikit-learn, PyTorch
Data and evaluation—Loading, caching, statistics, figures, configspandas, NumPy, pyarrow, SciPy, matplotlib, PyYAML
Application and quality—Explorer app, tests, lintingStreamlit, pytest, ruff

Every model reports AUROC and AUPRC with bootstrap CIs, alert burden at a validation-chosen 80% sensitivity, calibration slope and net benefit. Clusters report stability (adjusted Rand index) and outcome rates with 95% intervals.
